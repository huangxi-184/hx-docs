# Dify 1.19.0 功能核对清单

---

## 一、判定口径

原表用五级（全部满足 / 大部分满足 / 小部分满足 / 都不满足 / 空）。本文统一折算为四级，便于横向对比：

| 本文级别 | 含义 | 对应原表口径 |
|---|---|---|
| **满足** | 能力完整覆盖要求，无明显缺口 | 全部满足 |
| **基本满足** | 主干能力具备，缺边缘项（如缺评审流程、缺导出） | 大部分满足 |
| **部分满足** | 有对应能力但只覆盖要求的一部分维度 | 小部分满足 |
| **不满足** | 无该能力，或要求与产品形态不符 | 都不满足 |

## 二、总览

| 能力域 | 条目数 | 满足 | 基本满足 | 部分满足 | 不满足 |
|---|---|---|---|---|---|
| 模型管理 | 9 | 0 | 0 | 5 | 4 |
| 推理运行时管理 | 8 | 1 | 0 | 7 | 0 |
| 智能服务治理 | 9 | 0 | 1 | 7 | 1 |
| 智能体编排 | 11 | 1 | 3 | 7 | 0 |
| 知识与能力资产管理 | 6 | 0 | 0 | 4 | 2 |
| 智能应用管理 | 8 | 0 | 3 | 5 | 0 |
| 系统管理 | 5 | 0 | 0 | 5 | 0 |
| 软件运行环境 | 3 | 0 | 0 | 3 | 0 |
| 软件编写要求 | 1 | 1 | 0 | 0 | 0 |
| 软件界面设计要求 | 7 | 2 | 0 | 3 | 2 |
| **合计** | **67** | **5** | **7** | **46** | **9** |

一句话结论：Dify 是**应用层平台**（编排 / 知识 / 插件 强），不是**模型层平台**（模型仓、评测、灰度、运行时参数 弱）。原表有 9 条属于模型层或客户端形态，Dify 结构性做不到。

## 三、模型管理（9 条）

| # | 功能小类 | 原表要求要点 | Dify 实现与证据 | 判定 / 缺口 |
|---|---|---|---|---|
| 1 | 模型接入 | 多类型模型（LLM/多模态/Embedding）+ 多精度并存 + 在线离线统一 | 插件化模型供应商，覆盖 LLM / Embedding / Rerank / Speech2Text / TTS / Moderation 六类；OpenAI 兼容接口可接 vLLM、Ollama、Xinference、GPUStack | **部分**：不导入权重文件，无 BF16/GGUF 精度管理，离线模型须先自建推理服务再以 API 接入 |
| 2 | 模型能力画像 | 名称、类别、参数规模、许可证、推理格式、硬件、Benchmark、安全等级、生命周期 | 模型列表展示供应商、模型类型、上下文长度徽标（`model-name/index.tsx` 读 `context_size`）、能力标签（插件声明）、流式支持 | **部分**：无参数规模、许可证、推荐硬件、Benchmark、安全等级；无画像自动提取与按能力检索 |
| 3 | 模型生命周期管理 | 发现→评测→封装→灰度→发布→退役全流程 | 可配置并校验凭据、启用/停用模型、设系统默认模型；替换后应用侧引用不变 | **部分**：无流程化生命周期、无安全评估、无灰度验证与正式发布、无版本化回滚 |
| 4 | 模型评测 | 通用基准 + AI 能力 + 航电专业能力分层评测 | 社区版无评测模块（api 全仓无 evaluation 控制器） | **不满足**：缺 MMLU/HumanEval 类基准、缺 Tool Calling/长上下文评测、无评测报告与准入。注意：知识库若有「检索质量评测」属命中率评测，与模型能力评测不同 |
| 5 | 模型仓库与版本管理 | 原始/量化/优化/导出模型 + 历史版本 + 模型级权限 | 无 | **不满足**：Dify 不托管模型文件，无仓库与版本树 |
| 6 | 模型元数据与可追溯 | 来源、许可证、发布方、变更记录，分析结论→模型版本可追溯 | 模型名称/供应商/类型在模型配置与调用日志中可见 | **部分**：无许可证、发布方、变更记录；无全链路版本追溯 |
| 7 | 模型灰度与回滚 | 灰度发布、按比例切流、快速回滚、多版本并存 | 无 | **不满足**：切换模型立即对全部应用生效 |
| 8 | 模型合规与安全 | 许可证合规检查 + 数据泄漏检测 | 输入/输出双向 Moderation（关键词 + OpenAI/Azure Moderation），可配置审核动作 | **部分**：无许可证合规，无数据泄漏检测与脱敏 |
| 9 | 模型持续评估 | 生产环境持续评估与退化监测 | 无 | **不满足**：无效果退化监测、无再准入机制 |

## 四、推理运行时管理（8 条）

| # | 功能小类 | 原表要求要点 | Dify 实现与证据 | 判定 / 缺口 |
|---|---|---|---|---|
| 10 | 推理服务统一接入 | 标准接口对接算力，替换不影响上层 | Provider 抽象统一调用；模型切换对应用透明；后端可为自建或云 API | **部分**：不纳管算力设施；国产算力（昇腾 MindIE 等）需外部自行部署后接入 |
| 11 | 运行时配置管理 | 上下文长度、批大小、KV Cache、投机解码、前缀缓存，可复制迁移复现 | 应用级采样参数（temperature / top_p / max_tokens / response_format）+ 记忆窗口轮数 | **部分**：无 Runtime Profile 体系，无配置复制/迁移/环境复现 |
| 12 | 容器化与集群编排 | 容器化 + 集群编排 + 离线镜像仓库内网分发 | 官方 Docker Compose 一键部署（本次落地 16 容器）；镜像可离线导入；API/Worker 无状态可平移 K8s | **满足**：官方仅提供 compose，K8s 需社区 Helm 或自行改造（属边缘缺口） |
| 13 | 长期稳定与离线能力 | 运行时升级、配置迁移、环境复现、完全离线 | 全内网离线运行（本次部署无外网依赖）；插件支持 `.difypkg` 离线安装；数据本地化 | **基本**：无配置迁移与环境复现工具；多版本共存需部署多套实例 |
| 14 | 算力环境适配 | 适配异构算力，不绑定硬件，支撑国产化平滑迁移 | 平台自身不做推理、不绑定硬件；任何 OpenAI 兼容接口的国产算力服务均可接入 | **部分**：无国产算力/国产 OS 适配认证与预置镜像；迁移需推理层自解决 |
| 15 | 弹性伸缩与高可用 | 弹性伸缩、故障自愈、多副本容错 | API/Worker 无状态可水平扩容（共享 PG/Redis）；容器 restart 自愈 | **部分**：无 HPA、无跨节点调度、无故障转移；单机 compose 存在单点 |
| 16 | 推理效率优化 | 结果缓存复用、批处理、流式输出 | 全链路流式；「标注回复」命中相似问题直接复用人工答案（语义缓存） | **部分**：无批处理；推理级缓存取决于外部框架；无前缀缓存配置 |
| 17 | 推理安全与内容过滤 | 数据最小化 + 输入输出内容过滤 | 双向 Moderation；代码执行在隔离沙箱；出网经 SSRF 代理白名单 | **部分**：无数据最小化与脱敏，无敏感信息识别掩码 |

## 五、智能服务治理（9 条）

| # | 功能小类 | 原表要求要点 | Dify 实现与证据 | 判定 / 缺口 |
|---|---|---|---|---|
| 18 | 统一服务入口 | 屏蔽推理集群差异，OpenAI Compatible / REST / gRPC | 每应用统一 Service API（REST，`/v1/chat-messages`），API Key 鉴权、流式；应用可发布为 MCP Server | **部分**：无跨应用统一模型网关（OpenAI Compatible 聚合入口），无 gRPC |
| 19 | 模型路由与负载均衡 | 按任务类型自动选模型/节点，轮询/权重/故障转移 | 同一模型可配多份凭据并开启负载均衡（`ModelLoadBalancingService`、`load_balancing_config.py`） | **部分**：无按任务类型智能路由；无失败自动转移（`model_manager.py` 中 fallback 仅注释） |
| 20 | 可观测性 | 模型指标 + 智能体指标 + 应用指标 | 应用/Agent 监控 7 项：消息数、活跃用户、Token 用量、平均会话互动、用户满意度、Token 输出速度、总会话数；含 **Token 费用估算**（`total_price`/`currency`）；工作流节点级耗时与 Token | **部分**：无模型级指标（QPS/吞吐/GPU 利用率）；无工具调用次数、重试次数；无统一告警 |
| 21 | 业务链路追踪 | Prompt、上下文、Tool 调用、知识访问、输出的完整链路 | 工作流运行详情按 trace 串联节点输入输出、Prompt、上下文、知识检索结果与工具调用；支持单步调试与日志归档（`workflow-log-archives`） | **基本**：无 OpenTelemetry 标准分布式追踪；接 Langfuse/LangSmith 需装插件 |
| 22 | 安全与审计 | 鉴权、权限管理、审计日志、数据隔离、离线审计 | API Key、成员角色、**权限组（RBAC 权限点）**、**访问规则**、**IP 访问策略**、知识库成员级权限、工作区隔离、SSRF 代理与沙箱、资源访问令牌 | **部分**：社区版无操作审计日志；无项目级隔离；企业 SSO（SAML/LDAP）不在社区版（`api/enterprise/` 仅 telemetry） |
| 23 | 配额与成本控制 | 按用户/项目/智能体配额与计量 | 应用级**并发请求上限** `max_active_requests`（默认 0=不限，按应用配置）；Token 用量与费用估算 | **部分**：无按用户/项目的配额与计量，无预算控制与超限阻断（云端 credit 机制自托管不启用） |
| 24 | 策略治理 | 路由/限流/访问策略集中配置下发 | 应用级并发上限可配 | **部分**：无策略集中配置与下发，无差异化策略编排 |
| 25 | 多租户治理 | 多租户资源配额、数据隔离、归属管理 | 原生多工作区（tenant）隔离：成员、模型、知识库、应用均按工作区隔离 | **部分**：无租户级资源配额与计量，无跨租户归属管理 |
| 26 | 服务等级保障 | 按业务优先级 SLA 保障 | 无 | **不满足**：无 SLA 分级、优先级队列、重点任务资源保障 |

## 十三、原表未覆盖、但 Dify 具备的能力（正偏离候选）

以下功能在 67 条要求中没有对应条目，但属于 Dify 的实际优势，评估工作量时可视作正偏离：

| 能力 | 说明 |
|---|---|
| 可视化工作流画布 | 节点式编排、变量引用、单步调试、运行轨迹回放 |
| 工作流版本历史与回滚 | 已发布版本可恢复为草稿，带版本号与备注 |
| 应用 DSL 导入导出 | 整套编排（节点、变量、配置）可导出为 YAML 迁移复用 |
| 插件双通道安装 | 在线市场一键安装 + 离线 `.difypkg` 本地安装 |
| MCP 双向能力 | 既作客户端接入外部 MCP 工具，也可把应用发布为 MCP Server |
| 多凭据模型负载均衡 | 同一模型配置多份 API Key 做分流 |
| 人工介入节点 | 流程暂停等人填表/IM 确认，最长可挂 7 天（`HUMAN_INPUT_GLOBAL_TIMEOUT_SECONDS`） |
| 知识分段策略 | 父子分段、QA 分段、自定义分段规则 |
| 应用监控与费用估算 | 7 项指标 + Token 折算费用，按访问入口可拆分 |
| WebApp 免登录分享 | 应用直接生成可分享页面与 iframe 嵌入 |
| 双 API 出口 | Service API（面向外部调用）与 Console API（面向控制台）分离，作用域不同 |
| 沙箱与出网管控 | 代码执行隔离沙箱 + SSRF 代理白名单 |
